## HISTORIA

Como **ciudadano**, quiero **registrar una solicitud eligiendo el tipo de trámite y describiendo mi pedido**, para **iniciar el trámite sin ir a la institución y contar con un código para seguirlo**.

## CRITERIOS DE ACEPTACIÓN

1. Dado un tipo de trámite activo y los datos obligatorios completos, cuando el ciudadano confirma el registro, entonces el sistema crea la solicitud en estado «Recibida», calcula la fecha de vencimiento según el plazo del tipo y muestra un número de seguimiento único.
2. Dado un formulario con un campo obligatorio vacío, cuando el ciudadano intenta confirmar, entonces el sistema no crea la solicitud e indica qué falta.
3. Dada una solicitud registrada, cuando se consulta la bitácora, entonces figura el evento de creación con fecha, hora y origen del registro.

## DATOS DE REFINAMIENTO

- **Supuestos:** El ciudadano se identifica con datos de contacto; no se usan datos personales reales en la práctica.
- **Dependencias:** HU-01 (el tipo de trámite aporta el plazo y la dependencia).
- **Riesgos:** Números de seguimiento adivinables; se mitiga con un código aleatorio no secuencial.
- **Priority:** Must · **Story points:** 5 · **Epic:** Registro · **Business value:** 5
- **Orden en el backlog:** 2 de 16

- [ ] Registrar el evento de creación en la bitácora
