## HISTORIA

Como **ciudadano**, quiero **consultar el estado de mi solicitud con el número de seguimiento**, para **conocer cómo avanza mi trámite sin acudir a la institución**.

## CRITERIOS DE ACEPTACIÓN

1. Dado un número de seguimiento válido, cuando el ciudadano consulta, entonces ve el estado actual, la fecha de la última actualización y la dependencia responsable.
2. Dado un número inexistente, cuando consulta, entonces recibe un mensaje genérico que no revela información de otras solicitudes.
3. Dados cinco intentos fallidos desde el mismo origen en un minuto, cuando se intenta otra consulta, entonces el sistema la limita temporalmente.

## DATOS DE REFINAMIENTO

- **Supuestos:** La consulta es pública mediante el código; no requiere cuenta de usuario.
- **Dependencias:** HU-02.
- **Riesgos:** Enumeración de códigos para ver datos de terceros; se mitiga con el código aleatorio, el mensaje genérico y el límite de intentos.
- **Priority:** Must · **Story points:** 3 · **Epic:** Seguimiento · **Business value:** 5
- **Orden en el backlog:** 5 de 16

## TAREAS TÉCNICAS

- [ ] Definir el endpoint público de consulta por código
- [ ] Implementar la respuesta con estado, fecha de actualización y dependencia
- [ ] Agregar el mensaje genérico para códigos inexistentes
- [ ] Implementar el límite de intentos por origen
- [ ] Construir la pantalla de consulta y su versión para móvil
- [ ] Escribir pruebas de código válido, inexistente y límite de intentos
